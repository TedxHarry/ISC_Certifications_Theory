Use of the worked guide or targeted coaching is recorded as assistance, not labelled an uncoached attempt.

Store actual assessment records privately outside the reusable course folder. Use unused attempt names and keep saved-template references separate from generated campaigns.

## Evaluate evidence and judgment

Required evidence must support the actual scope and event, not a generic screenshot quota:

- Readiness, original data and planned allowed changes.
- Exact preview tuples and initial actual recipients.
- Saved draft/unsigned checkpoint and released update.
- Existing-work reassignment, actual new recipient, choice/history observations and final actors/sign-off.
- Matching removal work and complete file versions with successful collection/current account observations.
- Retained rights, untouched accounts and correctly scoped fresh reports.
- Case index connecting available actual IDs, objects, actors and time zones; gaps identified rather than fabricated.
- Closure or specific handover, followed by resolved reset readiness.

A report field can describe current reviewer, decision maker or final submission differently. Accept the actual coherent record; do not force every actor column to manager02. Do not accept a status label as a substitute for the account observation.

If an error occurs, assess whether the learner identifies the exact object/state, preserves evidence, investigates within authorized scope and chooses safe continuation or handover. Accurate handover can meet troubleshooting/communication criteria while the executed removal outcome remains incomplete.

A scope error or unauthorized change is not masked by an average score. Record the attempt, containment/correction and help used. Rework can be assessed, but do not erase the deviation or label coached repair an uncoached first pass.

## Separate result dimensions

Record these dimensions independently:

| Dimension | What can be recorded |
|---|---|
| CSV execution | Complete only when actual scope, review/handover, fulfillment, retained rights and evidence are established; otherwise incomplete/not ready/not run with reason. |
| Connected execution | Complete only from actual supported automatic target outcome and retained memberships; otherwise incomplete/not ready/not run. |
| Reset readiness | Ready only after exact starting sets and resolved outstanding work are verified. |
| Assistance | Record actual help, operator roles and who checked the run; self-checking is separate from independent observation. |

Assess CSV execution without requiring the optional connected outcome. Each attempted route needs all critical scope, recipient eligibility, justified choices/sign-off, actual work/result, retention and evidence checks before execution is complete. Record reset readiness separately: a completed result does not make the setup ready for another attempt until its reset is verified. A fully closed training attempt needs both completed execution and verified reset for the route attempted.

Record both the assistance used and whether the run was self-checked or independently observed. Neither one substitutes for the other. There is no required time, word, screenshot, percentage score or campaign-object quota.

Official-reference lookup is normal work. Distinguish it from an assessor supplying the solution or coaching the needed clicks. One human operating multiple synthetic sessions is transparent training execution, not independent human approval.

Do not infer professional production readiness for every integration, engine or specialist feature from this single bounded project.
