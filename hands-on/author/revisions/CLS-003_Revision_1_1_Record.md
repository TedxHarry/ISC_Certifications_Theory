## Useful teaching changes

A profile reference is the role's link to an existing profile. The correction removes that link rather than changing the shared Export profile or its permission. Approve/Revoke meanings are explained for role design before the review procedure; a Revoke comment requests the correction and does not edit the role automatically.

Identity, role owner, source owner, schema, type/multivalue, profile-holder and assignment meanings support the relevant actions. Define Assignment is explained as who receives the role, separate from what its profile list contains. The no-match criterion remains a checked training condition, not a production audience rule.

Legacy is explained as the older workflow used for this review type. Initial source creation, repeat reuse, successful catalogue loading, unused campaign names and separate saved/generated references are explicit. Actual route/eligibility and generated review units remain inspection gates.

The reviewer, selected authorized remediation owner, final submission and actual native edit remain separate stages. The actual final state/actor/time must establish sign-off. A saved comment, completed task or unchanged catalogue alone cannot establish the role correction.

The normal reset now rechecks zero role assignments/profile holders and unexpected requests/dependencies/operations before re-adding Export. Previously the reset repeated zero-state checks after adding the reference. If the boundary changed, the original restoration cannot proceed until the scope is resolved. The current F contract includes this pre-edit check. Legacy template cleanup matches the actual saved reference and preserves the completed campaign/reports.

The three existing tables, relationship sketch and wrong-object exercise remain. No new scenario, diagram, account fixture, rollout, global processing action or catalogue value was added.
