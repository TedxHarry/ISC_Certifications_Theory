## The learning experience

A beginner should be able to take a small certification task, prepare its inputs, perform the supported actions and explain the result using evidence. The explanation must stay understandable to a reader who uses English as an additional language.

The learner needs to know what exists before the action, what they are trying to achieve, which person or system acts, what changes and how to check it. A click path without those connections is incomplete teaching.

The first complete review comes early. Later labs introduce different decisions and problems rather than repeat the same setup with different names. Skills build on earlier work, but a person opening a particular lab can see its required starting state and locally explained supporting concepts.

A finished lab includes a useful opportunity to reason independently. The learner predicts or explains an outcome before opening the worked reasoning, then performs a changed task where the environment permits it.

## Approaches considered and chosen

Mirroring all61 theory lessons would repeat explanations and turn small concepts into unnecessary lab files. One large continuing company scenario would make later work depend on remembering earlier story details.

The chosen authoring approach is a small verified baseline, an early complete manager review, focused daily-task labs and separate job-dependent routes. The baseline uses neutral test records. Each lab identifies the dataset version or supplies its own setup and reset.

This approach follows the user's approved direction; the exact grouping and initial17 main/6 specialist inventory below are author design choices. Counts are planning results, not quotas. Split, merge or reorder unissued units when actual teaching or tenant constraints justify it. Record coverage moves.

## What the course will teach someone to do

Prepare a review requirement, identify the right data and decision unit, select people/access, inspect actual generated work, assign suitable reviewers, record and finalize justified choices, follow automatic or manual removal, investigate mismatches and produce a clear closure or handover.

The main route includes recognition of uncorrelated and machine accounts, package/role assignment origins, decision-support context and API evidence. A specialist route develops the corresponding operational workflow when that job or feature requires it.

Recognition has practical owners:002/004 check whether an account is an ordinary person's account, uncorrelated or used by a program;006/010 distinguish package/role review units and actions;010 inspects any available decision context;015 identifies when read-only API evidence could answer a report gap. These supporting explanations do not require an unavailable specialist licence or a coding exercise.

Neither course completion nor a scripted lab proves readiness for every production integration or future feature. The independent task and its observed evidence determine what competence was demonstrated.

## How each lab remains usable

State the actual starting facts, actors, test objects and required capability. Offer a verified seed/reset route where shared data is used. A reader who arrives later should not reconstruct hidden earlier changes.

Keep necessary ISC meanings near the action. Explain the user's choice and the documented system effect, then ask for a visible check. Distinguish a configuration screen, generated review, saved choice, final confirmation, task/operation and application state.

Screenshots must come from an actual authorized training run and be labelled with their relevant environment/version in author evidence. No stock or invented screenshot stands in for a result. The lab remains understandable when a screenshot is absent or a harmless visual label moves.

A small changed input should produce a reasoned investigation, not an instruction to copy the answer. The capstone provides evidence without first supplying the complete correction.

## What counts as complete

A learner file can be fully authored and documentation-checked before a tenant run. Record those as separate facts.

An executed lab needs the actual setup, actor, action, observations, outcome, useful changed-case reasoning and reset evidence. A different user must be able to repeat it without hidden author help before claiming independent repeatability.

Unavailable, blocked, partial, failed and not-run results remain those results. A lab missing target-removal proof does not pass its removal outcome. Actual competence is recorded per task, not inferred from reading every page.
