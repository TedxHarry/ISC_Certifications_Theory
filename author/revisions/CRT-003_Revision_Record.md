The user's continuation means the next complete learner after CRT-002. This work is local authoring; no new repository, commit, push, campaign, source mutation or deployment is included.

CRT-003 connects the application's existing access, ISC's collected information and identity association, generated review work, the reviewer's business decision and confirmation, applicable removal work, the account change and refreshed evidence. COV-02's process connection is primary. Detailed mechanisms owned by later lessons remain with those lessons.

The normal example uses a directly connected source with supported and authorized removal. A changed source capability introduces manual work. Exact removal timing and campaign completion order are not universalized.

## Example, branch and evidence consistency

Normal input: reports-user-1 belongs to its intended identity and holds individually reviewable reports-export; the person's current approved need is confirmed ended. Campaign includes the item with a suitable non-self reviewer. Revoke and confirmation are supplied, followed by confirmed ready removal work. Direct integration supports and is authorized for this removal. The application operation succeeds, a post-change exact-account permission list shows absence, and refreshed ISC data agrees.

Keep branch: an approved continuing need supports Approve. The removal portion does not apply to that item's decision.

Manual branch: remove direct write capability while preserving suitable reading. The actual assigned worker carries out required change; task closure alone is not substituted for correct-account verification. No trial mutation was performed.

Diagnostic cases each locate an unestablished stage: missing generated content, missing issued work, rejected source operation, and stale observation. No answer invents an automatic retry or concludes that a write failed merely because no write record is found.

Independent transfer changes the permission and introduces two accounts. Required work concerns invoice-approve on payments-approval; the completed task note names payments-basic. Old ISC information precedes task completion. Correct answer identifies exact-account evidence first, then refresh/reconciliation. A still-present right means the required outcome is unmet; a post-change absent right establishes that bounded account observation while task notes and ISC data still need reconciliation.
