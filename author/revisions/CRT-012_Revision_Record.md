## Brief prepared before drafting

Question: When should source owners review access? Develop COV-10's source-focused approach, with source ownership/knowledge and actual selected scope. Supporting COV-03/04/05/06/07/08/09/13/15/16/17/18/20 connects source configuration, collected account/access, association, eligible unit, reviewer rule, actual assignment, current need and result evidence. Do not repeat full manager correlation, query/filter configuration, ownership hierarchies, specialist account design or remediation procedures.

Teach the source-owner business question: appropriate access within a particular system across different people's accounts. Technical capability knowledge and business need evidence complement each other; title/ownership alone proves neither expertise nor permission to administer everything. Source configuration is not the actual application or employee account. Existing source owner, access owner, reviewer, campaign creator/owner and remediation responsibility must remain distinct.

Normal example: Reporting Production source has recorded owner owner-610, a suitable existing identity. Correct collected/correlated rep-310 and rep-311 accounts belong to different people/departments. RPT.EXPORT permits downloading reports; RPT.ADMIN permits changing report definitions and application settings. These are existing independently reviewable entitlements outside packages/automatic requirements. Campaign selects intended reporting source/access, no exclusion removes example units, actual generated assignment owner-610, active open review, appropriate authority and no self-review conflict. Owner knows capabilities; current-work evidence supports 310 export and ends 311 administrative need. Review judgments do not automatically change permissions or shared source/group configuration.

Explain source selection versus reviewer choice and the conditional Source Owner option in Search. Dedicated source-owner campaign generation requires owners on every included source. Do not invent fallback to creator/manager or conflate Access Owner's different hierarchy. Multiple selected sources/production-test sources retain separate source/account/owner context; owning several sources does not automatically select all of them or create a universal count.

Meaningful variations: wrong/stale owner, absent owner, absent/unqualified reviewer, changed owner after preview, source owner versus actual assignee/history, packages across sources and role/LCS boundaries, missing account/correlation, service/uncorrelated account recognition. Keep exact special-account inclusion conditional. Owning a source does not auto-start a campaign, prove every account is included or grant all ISC administration. Distinguish reviewing current assignments from changing shared permission definitions.

Independent transfer: Warehouse Production has current owner owner-720 after replacing owner-710; earlier generated active open unsigned review still assigned to owner-710. worker-402/wh-402 holds STOCK.ADJUST, allowing quantity changes; actual source/account/right and identity associations are correct, normal eligible entitlement/no self conflict. Current owner change is not proof review moved. Separately broaden requirement to include Warehouse Test, with no recorded owner and no existing generated coverage. Dedicated route needs owner readiness and actual new generated inclusion; no arbitrary creator fallback. Third changed requirement is active people's access across applications, requiring manager knowledge rather than assuming source expertise answers every people question.

One new working meaning: source-owner review. Existing owner/scope/record meanings are reintroduced locally. An editable dependency diagram and a responsibility comparison are useful only if they explain the topic. No quota/fictional biography, learner sources or meta-method statements. After completion: 12 authored topics, 38 unwritten; CRT-013 next. Preserve previous learner/asset/records, eight-entry manifest and reader implementation. No publication requested.
