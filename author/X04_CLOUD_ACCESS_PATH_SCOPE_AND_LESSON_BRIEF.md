## First complete learner brief

Question: How do you trace cloud access paths during a certification?

Start with removal of a temporary project entitlement while reading a production archive remains possible. Establish identity/account/source/entitlement locally, then define resource and the related cloud permissions.

Use one account and one named resource with two supplied, verified entitlement paths to reading. The review's target is the temporary project group, not the whole account or cloud resource. A continuing operational duty justifies the other path in the ordinary case. State that the group under review is independently eligible and no package/automatic assignment controls it.

Teach the actual assigned review's cloud detail/resource/path navigation. Compare Entitlement Path and All Paths and inspect resource scope, then use an editable two-path diagram to explain the expected effect of removing only the project path.

Record the justified project removal, final confirmation and supplied completed account-specific change. Verify the project membership gone, current path information refreshed and the retained reading path still authorized. No hidden queue, provider policy payload, instant refresh or whole-cloud-access guarantee.

Changed case: no remaining archive duty. One entitlement's removal does not complete the broader no-access requirement; accountable separate work must resolve the other verified path. A second variation switches to an access-profile review: inspecting cloud component details does not split the package decision.

End with a same-named test resource and missing activity context. Require resource/environment/path identification, actual permission meaning and current need before using observations or recording a result.
